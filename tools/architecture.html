End-to-End View

From Wallet Intent to an App Ecosystem

Participant wallets initiate proposals and identity-bearing actions. The validator cluster, release-flow governor, and IPFS-backed replication establish canonical Oak and JCR-backed state. Edge and gateway workers then normalize that truth into read models that many apps can consume, from Oak Ops to DA/live sites dedicated to genesis-state storytelling, provenance, and content reality.

Canonical Truth

Validator Network and State

The validator cluster, not any single app, is the source of truth. Raft term, release-flow state, confirmations, replicated Oak state, and the blockchain-backed JCR reality all originate there.

Platform Layer

Read-Model Fabric

Apps do not read raw validator internals directly. Edge adapters and workers project canonical state into app-specific contracts, including /ops/v1 locally and the hosted oak-chain-action bridge in EDS-hosted environments.

Flow

State Propagation Pipeline

Each layer narrows the system from canonical consensus state into reusable read models and then into fast-moving application surfaces.

Participants

Wallet Intent

Participant wallets carry identity, sign proposals, and introduce work into the mempool and confirmation path.

  • Wallet ownership and signing
  • Proposal ingress and confirmations
  • Release eligibility begins here

Consensus

Validator Network

Validators, leader election, release-flow stages, and replication create the canonical Oak state and blockchain-backed JCR truth the rest of the system must respect.

  • Leader and follower roles
  • Raft term, queue, and governor state
  • IPFS-backed durability and replicated content state

Edge Adapter

Gateway and Workers

A worker-backed gateway converts raw consensus data into a dashboard-safe read model with auth, CORS, and cache boundaries at the edge.

  • /ops/v1 contract for UI clients
  • oak-chain-action hosted bridge routes
  • Cloudflare and Adobe I/O edge execution paths

Apps

App Ecosystem

EDS pages, Oak Ops, DA/live properties, and future explorers render specialized views of the same underlying truth without taking direct consensus writes.

  • Oak Ops control plane
  • Genesis-state DA/live and storytelling sites
  • Read-only provenance, audit, and content-state explorers

Write Path

Canonical State Movement

  1. Participant wallet signs and submits intent.
  2. Validators ingest proposals into mempool and confirmation stages.
  3. Release-flow governor advances, holds, or overflows work based on cluster posture.
  4. Replication and IPFS-backed durability make the state globally recoverable.

Read Path

Read Models and Consumer Apps

  1. Edge or gateway worker reads consensus and explorer sources.
  2. Worker normalizes them into stable contracts and route bridges for different surfaces.
  3. Oak Ops, DA/live apps, and other EDS properties fetch those read models only.
  4. Each app expresses one slice of value without coupling directly to raw internals.

Operator

Oak Ops

Control-plane UX for release flow, signals, config drift, GC posture, and runtime debugging.

Storytelling

Genesis State Site

A dedicated DA/live property that turns genesis writes and early chain state into a public, legible narrative of why the content graph matters.

Truth Surface

Content-State Explorer

A focused app for inspecting Oak Chain JCR state, provenance, and replicated content facts directly as durable reality.

Velocity

AEM-Scale App Speed

The value is not one dashboard. The value is a platform that can spawn many focused apps as quickly as AEM properties do today.
